# RSVP Site Design

## Overview

A single-event RSVP site built with Next.js (App Router). Guests submit their name and email, receive a confirmation email via Resend, and the host can view all responses on a password-protected admin page.

## Tech Stack

- **Framework:** Next.js (App Router)
- **Package manager:** pnpm
- **Database:** MongoDB (via Mongoose)
- **Email:** Resend
- **Language:** TypeScript

## Pages & Routes

### `/` — RSVP Form (Public)
- Two fields: Name and Email
- Client-side validation: required fields, email format
- Server-side validation: email syntax + domain MX check
- On submit: Server Action saves to MongoDB, sends confirmation email, redirects to `/success`

### `/success` — Confirmation Page (Public)
- Simple "Thanks, we got your RSVP!" message
- No data input

### `/admin` — Admin Dashboard (Protected)
- Inline password prompt (single field)
- Password verified against `ADMIN_PASSWORD` env var
- On success: sets session cookie, renders table of all RSVPs
- Table shows: Name, Email, Submitted At
- No separate login page

## Data Model

MongoDB collection: `rsvps`

```
{
  name: String (required),
  email: String (required),
  createdAt: Date (auto-generated by Mongoose timestamps)
}
```

## Data Flow

1. Guest submits form → Client-side validation
2. Server Action receives data → validates email syntax + domain MX records
3. Save `{ name, email }` document to MongoDB `rsvps` collection
4. Send confirmation email via Resend to the guest's email
5. Guest redirected to `/success`

## Auth Model

- Admin page checks for a signed cookie (`admin_authed`)
- Cookie is set via a Server Action that verifies the submitted password against `ADMIN_PASSWORD`
- Cookie is session-only (no expiry), no database needed

## Email

- Transactional email sent via Resend API
- Template: simple text-based confirmation, e.g. "Thanks [Name], your RSVP has been received."

## Environment Variables

```
MONGODB_URI=mongodb+srv://<user>:<pass>@<cluster>/rsvp
RESEND_API_KEY=re_<key>
ADMIN_PASSWORD=<any string>
```

## Deployment

- Stateless — can deploy to Vercel, Railway, Fly, etc.
- All config via environment variables
- No file uploads or long-running processes

## Non-Goals

- No user accounts or registration
- No multiple events
- No plus-one or meal preference fields
- No email verification link flow (syntax + domain check only)
